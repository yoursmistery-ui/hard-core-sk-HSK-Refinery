# VSE 角色信息页空白 + Mouse position stack 泄漏 — 排查结论 (2026-08-25)

> 结论先行：**根因不是任何 C# 补丁、不是 defs 内容、不是存档自定义激情，而是 `Assemblies` 目录里遗留的多个同名 `VSE` 测试 DLL。** 它们被游戏一并加载导致类型冲突，信息页渲染抛异常 → 滚动栈泄漏 + 空白。

## 一、现象

- 选中/打开小人「角色信息页」时**内容空白**。
- 首次打开出现 `Mouse position stack is not empty. There were more calls to BeginScrollView than EndScrollView. Fixing.`（Root.Update → EnsureMousePositionStackEmpty），二次不出现，重载存档再出现。
- **禁用整个 Vanilla Skills Expanded mod → 立即恢复**（用户实测铁证）。

## 二、最终根因（2026-08-25 定论）

`...\RimWorld\Mods\Vanilla Skills Expanded\1.6\Assemblies\` 里遗留了之前调试会话的补丁产物：

```
VSE.dll.new
VSE.dll.p5
VSE.dll.p5.p6
VSE.dll.p5.p6.p7
VSE.dll.p5.p6.p7.p9
VSE.dll.bak_abc
VSEHSKFix.dll.bak
VSEHSKFix.dll.p10
```

**RimWorld 会加载 Assemblies 目录里的全部 `.dll`。** 这些文件与真正的 `VSE.dll` 是**同名装配体（assembly 名都是 VSE）**，被一起加载 → C# 类型/装配体冲突 → 角色信息页渲染抛异常 → `BeginScrollView` 后异常中断、`EndScrollView` 未执行 → 滚动栈泄漏 + 页面空白。

清理掉这些残留 DLL（只保留 `VSE.dll` + `VSEHSKFix.dll`）后，**无论 defs 怎么改都恢复正常**。

## 三、为何之前的排查方向全被误导（关键）

1. **「关掉 VSE 就恢复」** → 整 mod 关闭 = 该目录所有 dll 都不加载（真 VSE + 残留一起消失）→ 看似 VSE 本身问题。
2. **「把 VSE.dll 的 C# 补丁全空化（lazy/max-inert）仍泄漏」** → 只改了 `VSE.dll`，**残留 dll 从没被动过**，冲突依旧 → 误判「不是补丁」。
3. **「激情重置后仍泄漏」** → 存档自定义激情(3/4/5)是红鲱鱼（关闭 VSE 也照样报 118 条 `Exception parsing <passion>`，但不影响信息页）。
4. **「defs 内容 / 删除速度 stat」** → 均为误导；清理残留 dll 后，原版 defs 与删减 defs 都正常。

> 教训：排错时若某 mod 目录里有多份同名单文件（.new/.p5/.bak 等），必须优先排查——游戏会全部加载，同名装配体冲突是隐藏雷。
