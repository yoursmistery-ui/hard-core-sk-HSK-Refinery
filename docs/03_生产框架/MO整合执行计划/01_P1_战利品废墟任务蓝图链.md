# P1 · 战利品搜刮 + 废墟/藏身处 + 任务链 × 蓝图书门禁(优先级第一)

> 目标: 把 MO「主动探索获取」这条腿整体复刻进 `HSK工业科研大修`,并让它成为 112 本蓝图书的**主投放渠道**。零 MO DLL;可用 VEF(KCSG 结构生成 / VEF QuestNode,已核实 VEF Core 激活)。
> 数据源: MO 1.6 本地副本实读(`workshop\content\294100\3219596926\1.6\`)+ `_tmp\mo_decomp\` 反编译。

## 二、落地设计(命名一律 `RK_`/`Rustic_`)

### 2.1 自研层(并进 `BlueprintUnlockHSK.dll`,不新开程序集)

1. `Building_LootableHSK : Building_Casket` + `BuildingLootableExtensionHSK`(字段: `itemDefName`、`randomItems`、`isRandom`、`lootChance`、`lootCount`、`qualityRange`、`enemyKindDefs`、`enemySpawnChance`、`hostileEnemy`、`destroyOnOpen`、**新增 `blueprintTier`/`blueprintSeries`**)。
   - 产出优先走我们已有的 `ThingSetMaker_BlueprintReward`(蓝图书池,已支持按"未解锁系列"过滤)——**这是蓝图书融合的关键接入点**: 若 def 带 `blueprintTier`,开箱直接调 `BlueprintGateDatabase` 选一本该档未读卷册;否则按 `randomItems`/ThingSetMaker 随机。
   - 敌怪生成保留(改为可配 `ManhunterOnPatch`/Berserk),但默认只放原版动物/海盗,不放 MO 生物。
2. `RK.QuestInformationHSK`(DefModExtension)+ `CompProperties_QuestFinderHSK` + `Building_QuestScannerHSK` + `WorkGiver_OperateQuestHSK` + `GameComponent_QuestFinderHSK`:照抄语义,`CanFind()` 只数 `CompAffectedByFacilities` 链接件数(阈值/工时/onlyOnce 全来自 XML);`DoFind` 调 `QuestUtility.GenerateQuestAndMakeAvailable`。
3. Tick 铁律(AGENTS §9): 扫描进度只在 `WorkGiver` 作业时按 tick 计数累加,`GameComponent` 每 250 tick 才校验一次 onlyOnce 集合;不做每 tick 遍历地图。

### 2.3 与蓝图书体系的四个融合点(必做)

1. **开箱出书**: `BuildingLootableExtensionHSK.blueprintTier` → 直接调 `BlueprintGateDatabase` 取该档**未读**系列,保证"探索=定向获取"。
2. **藏宝图定档**: `RK_TornNote` 分 3 档(残页/半张/完整),对应 1/3/5 件链接件解锁的站点档位,奖励必含指定系列卷册。
3. **任务奖励双层**: 任务完成给钱/好感(RimQuest 现有),**站点内实物=蓝图书**(照抄 MO 的"任务=货币、loot=实物"设计)。
4. **onlyOnce 防刷**: 邪教三级链完成后写进 `GameComponent_QuestFinderHSK` 的完成集,与 `BlueprintUnlockTracker` 的"已读集合"共用持久化槽位。

与计划的三处偏离(都有理由):

1. **书类产出用 `ThingMaker.MakeThing` 而非 MO 的 `BookUtility.MakeBook`** —— `MakeBook` 会随机覆盖书名,而我们的蓝图书要求"书名 = def.label"(v4.1 设计);另外蓝图书靠 `BlueprintTargetExtension` 认书,不靠随机书名。
2. **容器 `tickerType=None`**(MO 原档是 `Normal`)—— 搜刮容器无需 tick,符合 AGENTS §9;全部生成逻辑只在 `SpawnSetup`(非读档)与 `Open/EjectContents` 触发。
3. **容器一律不可建造**(不写 `designationCategory`、`costList Inherit=False`,并清掉 HSK `BuildingBase` 继承来的 `researchPrerequisites`)—— 避免污染建筑师菜单;M2 用 KCSG 站点投放后,它们只作为"发现物"存在。

踩坑记录: `Verse.LoadSaveMode` 在 1.6 没有 `InPlay`(用 `== LoadSaveMode.Inactive` 判"游戏中");`Room.IsHoused` 不存在(改用 `!x.Roofed(map)` 保证遗栈落在露天);`Verse.Mathf` 在本文件不可裸用 `Mathf.*`(自带 `ClampI`);`Bone`/`Book` 在本环境不是 defName(骸骨堆改 Steel/Silver/Cloth,书堆产 `TextBook`)。

**待游戏内验证(同步后)**: 开发者模式摆一个 `Rustic_LootBarrelClosed` → 小人右键"打开" → 物品掉出 + 贴图变暗色空桶;事件 `RK_Incident_RuinCache` 触发一次;圣物柜能翻出 5 档蓝图书且标签显示〔未读〕。

## 三、里程碑与验收

- M1(自研骨架): `LootableHSK` + 6 件废墟 Lootable 上线 → 验收: 地图上生成的废墟可搜刮、能出蓝图书、能出自定义物品、无异常。
- M2(站点+任务): 3 套 KCSG + 4 个 QuestScriptDef → 验收: 小废墟任务能自然刷出、进去能搜到书、清剿可完成;与 RimQuest 并存不炸。
- M3(扫描链): 信鸽站/信使台/探秘桌 + 三级解锁 → 验收: 1/5/9 件链接件分别解锁 1/2/3 级;邪教任务 weight=0 只能扫出。
- 每步做完: `build.ps1` 重编译 → 清 MissileGirl 缓存 → 启动读 `Player.log` → 双目录同步 hash 核对。
