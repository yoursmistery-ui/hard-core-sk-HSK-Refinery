1.1 炉衬耗材 + 进度条（替代耐久度）纯 XML推荐

反编译 CompProperties_Refuelable 核实可用：fuelCapacity、fuelConsumptionRate（/60000，按游戏日标定）、consumeFuelOnlyWhenUsed、fuelFilter、minimumFueledThreshold、drawFuelGaugeInMap、canEjectFuel。

  • 条 = 炉衬余量，随使用下降；fuelFilter 只放 RK_Met_Firebrick，小人靠原生 refuel job 自动搬砖补炉衬，零代码；配 tickerType=Normal
  • 烧穿的替代表现：低于 minimumFueledThreshold → 熄火 + 原生 OutOfFuel 覆盖层。不炸不刷火，避免"造两座轮流用"反模式
  • 砖在 Refuel() 里被 Destroy() 转成数值 = "砌进炉衬"；另一种"积渣上涨型"的代价见 Q1（详论在 md）

1.2 矿渣副产物 纯 XML

  • RecipeDef 的 <products> 原生支持多产物，不需要 ProcessorFramework
  • 雷区 严禁为此新建 ProcessDef：融合版 ProcessorFramework.dll 的 thingDef 是运行时 ActiveProcess 型，原版写法反序列化失败 → 整 def 不加载 + processes 交叉引用报错
  • 产渣量随品位静态写死（贫矿多、富矿少）；矿渣保持实物（落地/进库存）才能进下游配方
  • 闭环三下游：矿渣砖/水泥→建筑｜回收残余铁→复用现成 ExtractMetalFromSlag｜回填铺地

1.3 高炉温度 纯 XML

  • 显示：新 StatDef RK_Met_FurnaceTemp（unit=Celsius），各炉 statBases 写定值（1250/1500/1600/3000…）
  • 代价：SK.CompProperties_HeatPusherAdvanced（Core_SK 现成，Odyssey 用到 heatPushMaxTemperature=250）→ 炉周房间升温，原生热射病/灼伤、食物腐坏加速、舒适度崩
  • 硬门禁的真相：原版 RecipeDef 读不到建筑 stat，"谁能炼什么"仍由配方挂哪座炉决定；温度给的是叙事 + 布局惩罚。要"温度决定产物档"→ 拆同级多座炉（高炉 I/II/III），不是给单座炉加动态判定

1.4 耐火材料门禁 纯 XML

  • 新 ThingDef RK_Met_Firebrick：SoftClay + ChunkLimestone/CrushedStone 在 Kiln 烧制，挂 Ceramics_A1 → B1（这就是"耐火材料攀升"入口）
  • 落位法=追加 costList。不动 stuffCategories：TableFurnace 现为 Stony|Bricks × 240，改专用 stuff 类别会引入颜色遮罩并拖累所有同类可塑建筑
  • 改造四座：TableFurnace、Bloomery、Finery、Kiln（原 costList 保留，只追加）
  • 必查 新增建筑必须补 uiIconPath 且指向真实单张 png（stuffable 缺之 → 点选每帧 NRE"一点就卡死"）；三座现有炉已有，Kiln/新增件要查

1.5 钢体系归一 影响面最大 · 最后做

乱点

  • PigIron 生铁 与 CastIron 铸铁 同物两名；五档钢名机翻杂乱（WroughtIron/ForgedSteel/BlisterSteel/CrucibleSteel/WootzSteel + "锻造剪切钢"异名）
  • SLDBar/USLDBar 把熟铁(0.75)·锻钢(1.2)·乌兹(3.0)混进同一池 → CE 弹药金属返还永远取最便宜的熟铁（改类别会连带改返还）
  • 与 MS 的 CarbonSteel/SpringSteel/ToolSteel/MildSteel/AR500 无清晰承接

统一四招 defName 一律不动（1759 配方交叉引用 + 本 mod 147 件物品在消耗这些钢）

  • ① 中文 label 排成念得通的阶梯：熟铁 → 锻钢 → 坩埚钢 → 乌兹钢 → 合金钢；走 HSK附属mod汉化/1.6/Vile's Metallurgy/...
  • ② 每档钢独立 stuffProps + 独立可用档——升级动力从耐久挪到这里
  • ③ 去重：PigIron 为唯一中间物，CastIron 用途化成"铸件料"；BlisterSteel 只由渗碳炉产、只被坩埚钢消耗
  • ④ 研究档对齐 HSK 六档台（铁器 → PrimitiveResearchBench/SimpleResearchBench，钢 → LabTerminal）；SK.AdvancedResearchExtension.requiredResearchBuildings 是硬门槛

2 明确不做 出局
