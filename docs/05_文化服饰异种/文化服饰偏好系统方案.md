# 鼠族 + 美狐 文化服饰偏好系统 — 全量方案 v1

> 目标: 让 5 个文化圈(骑士王国/异邦/军阀/金鸢尾兰/美狐)的 NPC 与玩家在"穿什么"上有**明确分区**(内衣/常服/护甲/大衣/头饰/面饰/配饰/背具)和**派系偏好**(xx 族更偏好 xx 衣),花样克制、允许跨文化重复。
> 铁律: 不碰基础衣物 def 本体(用补丁 Add 属性), 不改派系 pawnKind 生成链以外的东西, 优先纯 XML。

---

## §0. 机制地基(全部经反编译验证)

游戏"决定一个 pawn 穿哪件"的最终分布,由这条加权链控制:

```
候选衣物集合(按 bodyPartGroup 过滤 + tag 匹配)
   → TryRandomElementByWeight(pa => pa.Commonality)
        → ThingStuffPair.Commonality = thingDef.commonality × thingDef.generateCommonality × stuff.commonality
```

- `Verse/ThingStuffPair.cs:44` — `num *= thing.generateCommonality;` 证实每件衣服的 `generateCommonality` 直接乘进权重。
- `RimWorld/PawnApparelGenerator.cs:877/895/933` 等 — 派系服装生成的每一处都走 `TryRandomElementByWeight(x => x.Commonality)`。

结论: **给每件衣物设不同的 `<generateCommonality>`,就能精确控制同池内的出现比例**,不需要风格类目、不需要补 Styleable comp、不需要新贴图。

三条并存的挂载路径(可叠加):

| 路径 | 载体 | 粒度 | 适用 |
|---|---|---|---|
| A. 职位服装(现用) | `PreceptDef[IdeoRole_*].roleApparelRequirements` + `allowedFactionCategoryTags` + `requiredTags/requiredDefs` | 按派系 categoryTag + 按职位 | 军阀/骑士/美狐等 NPC 派系 |
| B. pawnKind 服装池 | `PawnKindDef.apparel`(`SpecificApparelRequirement`: `RequiredTag` / `AlternateTagChoices{tag,chance}`) + `apparelTags` | 按兵种/职业 | 玩家开局兵、各职业鼠 |
| C. generateCommonality | 每件 `ThingDef` 上 | 全局权重 | 所有路径共用的偏好底座 |

关键区别: `requiredDefs`/`requiredTags` **只圈定候选池**;真正的偏好比例靠每件 def 的 `generateCommonality`(路径 C)决定。这正是"xx 族偏好 xx 衣"的实现点。

现状(见同目录 `服饰分区盘点.csv`,按 defName 去重 347 件: 鼠族212 / 金鼠族77 / 美狐57 / 原版文化拓展1):
- **315 件已有 apparel tag**,32 件无 tag(不补则永不进池,需确认是否故意排除)。
- **仅 43 件显式设了 `generateCommonality`**(多为 1、少数 0.1),**其余 300+ 件吃默认值**(注意:字段默认是 1,不是 100——之前"默认100"表述作废,以反编译 ThingStuffPair.cs:44 为准)。权重体系基本空白。
- 已有丰富池标签: `RK_Knight(14)/RK_Noble(14)/RK_ExoticTier1-3/MihoMilitia(26)/MihoRoyal(21)/MihoCommon(15)/RoyalTier2-7/OARatkin_*` 等 —— 分区/文化归类的原材料齐备,但**没有一个"身体分区"维度**,全是文化/层级/职业维度。
- 层用量: OnSkin32 / Overhead24 / Shell20 / Middle17 / Miho_Under12 / Miho_Special8 / Belt2 / OuterClothing1 / kuabao2 / yaodai1 / EyeCover1 / xinpianA1。

## §1. 派系 categoryTag 现状与缺口

文化自定义可选项/派系偏好都要先能"认出这是哪个文化的人"。当前 categoryTag 分布:

| 派系 | categoryTag | allowedCultures | 问题 |
|---|---|---|---|
| Rakinia_WhiteRoseKingdom | `RatkinStory` | RK_Culture_Virtuard | 与军阀等混用同 tag,无法区分偏好 |
| Rakinia_CentralAlliance | `RatkinStory` | RK_Culture_Virtuard | 同上 |
| Rakinia_Exotic / ExoticBandit | (无) | — | 异邦无 categoryTag → 路径 A 完全无法命中 |
| Rakinia_Warlord | (无) | — | 军阀同上 |
| OA_RK_Faction | `OA_RK_Faction` | OA_RK_RatkiniaTraditionCulture | OK,独立 tag |
| Miho_Faction_Megacorp / Supremacist | `Mihoic` | MihoCultures | 美狐共用一个 tag,内部分支区分不了 |
| RK_Faction_Caravan | `RatkinCaravan` | RK_Culture_Virtuard | OK |
| RK_PlayerFaction / Miho_PlayerColony | (无) | — | 玩家派系无 tag,靠路径 B 兜底 |

设计: 给每个文化一套**独占 categoryTag**(在派系 def 或补丁里补),路径 A 的 `allowedFactionCategoryTags` 只认这些新 tag。

```
Culture_KnightKingdom   ← WhiteRose/CentralAlliance/Caravan
Culture_Exotic          ← Exotic/ExoticBandit/ExoticAncient/PlayerExotic
Culture_Warlord         ← Warlord
Culture_GoldenIris      ← OA_RK_Faction (沿用)
Culture_Miho            ← Megacorp/Supremacist/PlayerColony
```

> ⚠ categoryTag 还被派系生成/外交别处引用,改前先 grep 该 tag 全项目引用数,新 tag 只做"加法"(补丁 `<li>` 追加到 allowedFactionCategoryTags),不改派系自身 categoryTag 语义 —— 详见 §6 风险。

## §2. 8 分区 tag 体系(本次核心交付)

给每件入选服饰打**一个分区 tag**(`Zone_*`),与现有文化/层级 tag 并存(允许一件多 tag)。分区即"衣柜抽屉",文化偏好在每个抽屉里挑。

| 分区 tag | 含义 | 对应引擎层 | bodyPartGroup |
|---|---|---|---|
| `Zone_Underwear` | 内衣/贴身 | Miho_Under / OnSkin(Full) | Torso, Legs, Neck |
| `Zone_Base` | 常服(衬衫/制服/袍) | OnSkin | Torso, Arms, Legs, Neck, Shoulders |
| `Zone_Armor` | 护甲 | Middle / Shell | Torso, Arms, Shoulders, Legs |
| `Zone_Coat` | 大衣/外套 | Shell / OuterClothing / Belt | Torso, Arms, Shoulders, Neck |
| `Zone_Head` | 头饰 | Overhead | UpperHead, FullHead |
| `Zone_Face` | 面饰(眼镜/口罩/面纱) | EyeCover / Miho_Special | Eyes, Mouth, Teeth |
| `Zone_Accessory` | 配饰(勋章/绶带/挎包/腰包) | Belt / kuabao / yaodai / Amulet / Ring / Wrist | Waist, Neck, Shoulders, Hands |
| `Zone_Back` | 背具(背包/斗篷背挂) | BackPack / InnerCoat | Shoulders, Back |

命名走 `Zone_` 前缀避免与现有 `RK_*`/`Royal*`/`Miho*` 冲突,且一眼可辨是"分区"而非"文化"。允许重复: 同一件 `RK_MedalHonor` 可同时是 `Zone_Accessory` + 多文化池 tag。

## §3. 文化 × 分区 偏好矩阵

每个文化在 8 分区里各放 1-3 类候选,用 `generateCommonality` 拉偏好梯度。示例(数值=相对权重,1=常见基准,可调):

| 文化 | Zone_Head 偏好 | Zone_Base 偏好 | Zone_Coat 偏好 | 风格一句话 |
|---|---|---|---|---|
| 骑士王国 | KnightHelmet1.5 / Crown0.3 | KnightTunic1.0 | Cloak1.2 / Mantle0.4 | 正装+纹章斗篷 |
| 异邦 | Turban/Fez1.5 / StrawHat0.6 | SilkRobe1.2 | 长披风1.0 | 异域织物 |
| 军阀 | Cap/Helmet1.4 | 制式军服1.3 | 野战大衣1.1 | 实用硬朗 |
| 金鸢尾兰 | 礼冠1.3 | 礼服1.4 | 披风0.6 | 宫廷礼仪 |
| 美狐 | 耳饰帽1.3 / 巫女头饰0.5 | 和服/巫女服1.3 | 冬外套1.0 | 和风 |

> 花样不太多: 每文化每分区只留 1 主导 + 1-2 次要,不做全展开。缺贴图新款式的分区(如美狐无大衣本体)→ 该格留空或借用鼠族同层 def,靠 tag 允许跨文化复用。

## §6. 风险与边界

- **categoryTag 复用风险**: `RatkinStory` 等被外交/生成引用,不擅自改派系自身 tag;新增文化 tag 优先用"补丁给 def 追加 categoryTag"不可行(categoryTag 单值)。→ 方案改为: 复用现有 tag + `anyMemeRequired`/pawnKind 区分,或确实需要时逐派系评估再换 tag。
- **generateCommonality 全局性**: 它是 def 级、不分派系,改高某件=对所有引用它的池都变常见。若要"A 族常见 B 族稀有同一件",必须靠**不同池 tag**(Zone+Culture 组合)隔离,不能只靠权重。
- **无 tag 的 40 件**: 不补 tag 就永远不进池,需确认是否遗漏(可能故意排除)。
- **CE bulk/甲值**: 本方案纯改分配,不碰 §7 CE 数值,但新增美狐职位服饰引用时注意 CE。
- **双目录同步**: 每步改完立即工作区↔部署 Mods 逐文件同步 + hash 核对。
