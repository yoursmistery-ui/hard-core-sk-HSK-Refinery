§0 现状诊断

910 件服饰，Apparel 树下 116 个分类节点，31 个平级挤在一级。根因是五套互不相容的分类轴被当成同级兄弟：

轴 代表节点
A 穿戴层(Core_SK) UpperDressCat 衣物上衣 / PantsCat 下衣 / VestsCat 背心 / BodySuitsCat / FullArmorCat / Headgear / BootsCat / GlovesCat
B 穿戴层(Vile's Pre-Industrial，与 A 平行重叠) BaseLayerCat 内衣 / MiddleLayerCat / ShellLayerCat / CombinedArmorCat
C 用途性质 ApparelArmor 装甲衣物 / ApparelNoble 贵族 / ApparelUtility 辅助 / ApparelMisc 杂项 / SpecialApparelCat 特殊装备 / ShieldCat 盾牌 / AccessoriesCat 配件 / KidsApparel
D 种族来源 RK_Apparel(225 件)、Miho_Apparel(56)、Kurin_Apparel(64)、OARatkin_*、Meow_*、RK_Scroll
E 身份套装 Sets(截图"按用途分类") + 33 子

病灶：263 件(29%)有 ≥2 分类，几乎全是 Set* 重复挂一遍（Apparel_TunicPoor → MiddleLayerCat+SetMedieval+SetCommoner+SetSlaver+SetHarvester）。标签撞车（headgear×2、shields×3、Full Armor×3、Heavy/Light/Medium Armor 各 2~3 份挂在三个不同父节点下）；13 个空节点（Hazmat/Mopp/Loadout/Sets/PreModernSets/SetJet/Shields/VFEC_Shields/UpperDressCat/HeavyUpperArmorCat/Kurin_Apparel/Kurin_Apparel_Middle/RK_HeadgearNoble）；Miho_Apparel 的 label 还是韩文 미호 의상。

底层数据质量：Backpack(12) 与 BackPack(8) 两套大小写；6 件 layers 内重复（Belt/Belt、Overhead/Overhead、Waist/Waist）；Apparel_HeavyShield 无任何分类。⚠ Overhead 是头顶层（帽/盔），不是外层大衣——按字面理解会整批判错。

§1 引用安全边界（已核，决定能动什么）

  • 全 236 个 mod 的 DLL 零硬引用 Set*、种族桶、*LayerCat 的 defName（扫描器用 Apparel/CombatExtended 做对照验证）。分类消费全走 XML 数据驱动。
  • 唯二 XML 硬引用，必须保命：① SetChemicalProtectionSuit → Core_SK\Defs\TraderKindDefs\TraderKinds_Orbital_DeepSpaceMining.xml 的 StockGenerator_Category.categoryDef（深空采矿船库存）；② 7 个层分类（Base/Middle/Shell/Combined Layer + Middle/ShellFull/ShellPartial Armor）→ HMC Vile's Pre-Industrial\Patches\Vile_Mending.xml 的 ingredients.filter.categories + fixedIngredientFilter（修甲配方收料）。
  • ∴ 只改 parent/label/成员挂载，绝不删 def、绝不改 defName（改 parent 不影响成员关系，上面两处都安全）。
  • <apparelTags>/<tags> 里的 RK_Apparel、OARatkin_Apparel、Meow_* 等同名字符串属另一命名空间（PawnApparelGenerator 只做字符串比对），是文化穿搭池标签，勿动。
  • 截图顶部三个 *技术等级 不是分类，是 Core_SK 的 6 个 SpecialThingFilterDef（AllowApparelNeolithic…Ultra/Archotech）。该类型无 displayOrder 字段，顺序由 def 加载序决定、XML 不可排 → 保持原样，不并入新树。ThingCategoryDef.displayOrderInCategory 可用，新树顺序靠它。

§2.1 复用清单（13 复用 / 9 新建）

归属先分清：原版 Data/Core 只定义 8 个服饰分类（Apparel/Headgear/ApparelArmor/ArmorHeadgear/ApparelUtility/ApparelNoble/HeadgearNoble/ApparelMisc）；其余 *Cat 是 Core_SK 自研；Base/Middle/Shell/Combined LayerCat = Vile's Pre-Industrial；Loadout/Shields=CE；Hazmat/Mopp=Rimatomics_SK；Meow_*=本地鼠族HSK拓展。逐节点成员与判定依据见 服饰分类重整_映射表.csv 的「复用为新节点」列。

  • ①穿戴位置 9 个全部复用，0 新建：贴身内衣=BaseLayerCat(Vile PI，⚠被 Vile_Mending.xml ThingFilter 引用，只改 label/parent、成员不动)、躯干外衣=UpperDressCat(子节点 29 件正好当三级)、全身连体=FullBodySuitsCat、下衣=PantsCat、鞋=BootsCat、手套=GlovesCat、头部=Headgear(原版，最稳)、面饰=AccessoriesCat(9 件全是夜视/护目/墨镜/耳罩，语义正好；GasMasksCat 收为其子)、配饰腰背=ApparelMisc(顺手并入 CE Loadout/Shields/VFEC_Shields 三空壳)。
  • ②用途 7 个复用 4：礼仪=ApparelNoble、战斗护甲=ApparelArmor(近空壳当骨架，FullArmorCat/各 *ArmorCat/ShieldCat 收为其子)、战术装备=ApparelUtility(20 件全是护盾带/跳包/轨道指示器，语义完全对得上；混装的 SpecialApparelCat 降为其子)、装饰=Meow_Jewelry(自家 def)。
  • ④身份套装：Sets+33 原样保留（Core_SK 23 / Vile PI 12，§1 已核零 DLL 引用）。

必须新建 9 个：②日常便服、②职业劳作、②环境防护（Core_SK 把职业全散在 Set* 里、无独立用途类；防化只有 Rimatomics 空壳）、③科技档 6（Core_SK 完全没有服饰科技档分类，只有 §1 那 6 个不可排序的 SpecialThingFilterDef）。科技档沿用本仓 RK_Bar_* 先例 → RK_Apparel_Neolithic/Medieval/Industrial/Spacer/Ultra/Archotech，label 直写中文。顺带：BodySuitsCat(16，实为 T恤/衬衫/医护服) 降级为躯干外衣子节点不另立；空壳 SetJet/HeavyUpperArmorCat/RK_HeadgearNoble 一并收掉。

§3 三轴判定规则（已跑通全量，可复算）

  • ③ 科技档：直取 techLevel，零歧义。HSK 的"电力/石化"是科研树概念、不是 def 字段，browse 层用 techLevel 六值。
  • ① 穿戴位置：优先级 旧功能分类 > Zone_* tag > layers > bodyPartGroups。三信号一致 635/910(70%)，冲突 275 件集中在"OnSkin 层的制服/常服"(109) 与"甲类算全身还是躯干"(29)——属语义选择而非数据错误，按优先级定档并全量落表可复核。① 的 9 类直接复用既有 Zone_* 8 分区 tag（见 文化服饰偏好系统方案.md），让浏览树与文化穿搭共用一套口径，不再造第四套。
  • ② 用途场景：旧分类映射 → 甲类分类或护甲值≥4 判战斗护甲 → Set* 职业/战斗归属 → 按 techLevel 兜底日常便服。⚠ 薄弱点: 55 件靠"护甲值≥1"兜底判成战斗护甲（如 airwire headset 通讯耳机），P2 需抽检并收紧阈值。另 22 件（轨道轰炸指示器/心灵投射枪/控制包/连体工作服/热力大衣）已人工裁决，清单在 _tmp/apparel_cat/finalize.py 的 MANUAL。

写法三条硬约束

  1. 模板照抄 52_弹药分类统一.xml——它已验证过同一套动作（新建中类 + 顶层 Conditional 门控 + Replace parent 收拢），弹药分类树就是这么收编的。
  2. PatchOperation 不解析继承: 只补原始 XML 里自带 thingCategories 的 def；靠基类继承分类的，须打到基类 [Name="XXXBase"] 或在子类自身 Add 完整列表。
  3. 父子 def 不得同时补同一分类（AGENTS §3，会撞 duplicate thingCategory）——补之前在原始 Defs 上按 ParentName 链排查；两分支 value 一律带 Inherit="False" 挡父类旧列表项。
