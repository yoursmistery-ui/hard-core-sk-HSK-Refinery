# 补丁编写铁律(HSK 整合)

> 来源: AGENTS.md §3 关键坑 + §5/§6 相关条目。以下任一条踩中都会导致补丁静默失败或游戏报错,动手前逐条对照。

## 1. 关自动配方
- Replace 整段 `recipeMaker` 为 `IsNull` **不生效**。
- 须 `Add <recipeMaker Inherit="False" IsNull="True"/>` 到 **ThingDef** 自身(12 号补丁: 先条件 Remove 再 Add)。
- 改自动配方所在工作台: 整体 Replace/Add `recipeMaker` + `Inherit="false"`(深度合并,否则 recipeUsers 合并挂两台)。

## 2. PatchOperation 操作原始 XML,不解析继承
- 子类无自有节点(继承 Abstract 基类)时 xpath 报 `"Failed to find a node"`。
- 须打基类 `[Name="XXXBase"]`,或 Add 到 ThingDef 自身。

## 3. xpath 语法限制
- **不支持 union(`A|B`)**: 必须拆成多个 Operation。
- `PatchOperationConditional` 的 `nomatch` 分支里 Add 的目标节点**必须存在**。

## 4. 补丁执行顺序 = 文件名(字符串)序
- **`1xx_` 是陷阱编号**: `'1'` < `'3'/'5'/'9'`,`105_` 实际排在 `11/32/52/91` 号**之前**(与 100-103 军阀补丁同段)。
- **永远不要把 `1xx` 当"最终层补丁"**——它引用 32/52/91 号 Add 的节点时,目标尚未存在 → Replace 全报 "Failed to find a node"。
- 要"最后执行"必须用 **>91 的两位数编号**或并入 **92 号末尾**。
- 引用其它补丁 Add 的节点时,须验证**目标补丁文件名序在自身之前**,不能只看节点全局存在性。

## 5. 1.6 起 Operation 级 `MayRequire` 已失效
- 反编译确认 1.6.4871 的 `PatchOperation` 字段仅 sourceFile/neverSucceeded/success,**无 MayRequire**;`Apply`/`Conditional` 均不检查。
- 未装目标 mod 时操作仍执行 → 报错。**根治: 一律用 xpath 存在性门控**(外层 `PatchOperationConditional` 检查目标 def 节点是否存在;不存在整段跳过)或 `PatchOperationFindMod`(mods 列表)。
- **Def 节点级 `MayRequire`(如 `<li MayRequire="Ludeon.RimWorld.Biotech">`)仍有效**,勿删。

## 6. 禁用 `FindMod`+`Sequence` 嵌套
- 1.6 实测不生效(实例: 03 文化职位适配 C/D 用 `FindMod(Ideology)+Sequence` 包职位 li → 职位池从未被应用)。
- **根治: 一律顶层独立 Operation**(原版职位用顶层 Conditional + match=Replace/nomatch=Add;VME/可选 mod 用顶层 Conditional + Sequence)。

## 7. 验证手段
- 改补丁后必须用 `_tmp/patch_simulator.py`(lxml)模拟执行验证。lxml 与 .NET 语义差异: xpath 无前导 `/` 时统一加 `/`;Sequence 的 operations 子元素 tag 是 `li`;Conditional/FindMod 的 match 是单个 Operation 整体递归。

## 8. 其它易错点
- **汉化文件夹必须 `ChineseSimplified (简体中文)`**(带后缀),否则 Languages 不加载。
- **汉化 DefInjected 结构**: 根节点 `<LanguageData>`,defName 作**节点名**(`<ThingDef><X><label>..</label></X></ThingDef>`);写成 `<Defs>`+`<defName>值</defName>` 会被**静默跳过、日志无报错**。
- **About.xml/description 不能含未转义 `<tag>`**(整 mod 被静默移出 ModsConfig);写完 `ET.parse` 验证。
- 改补丁后清 MissileGirl XML 缓存。
- `GameComponent` 子类须写 `public X(Game game)`。
- **ResearchTreeSK 重复解锁警告**: 同一无门槛配方挂 2+ 同研究解锁的工作台 → 启动报 "have duplicate unlocked defs";根治: 给配方补 `<researchPrerequisite>` 或从一个工作台删该配方/recipeUsers。
- **RecipeDef 同挂 researchPrerequisite+researchPrerequisites 告警**: 继承 `BaseMakeableGun`(其 recipeMaker 带单 researchPrerequisite=Gunsmithing)的枪,子类 recipeMaker 另写复数列表 → 深度合并后并存;根治: 子类 recipeMaker 内 Add 空 `<researchPrerequisite Inherit="false" />` 屏蔽继承。
- **Harmony 声明式补丁重载歧义**: `[HarmonyPatch(typeof(X),"方法名")]` 不指定参数类型 + 目标有多重载 → `AmbiguousMatchException` 且**连带同程序集整个 PatchAll 崩**;根治: 只 patch 无重载方法,或用 `[HarmonyPatch(typeof(X),"方法名",new Type[]{...})]`。
- **类名可见性**: 补丁引用跨 mod 类(如 `PawnRenderNodeProperties_EarHideByApparelTag` 在 RatkinRaceHSK 的 NewRatkin.dll)只要目标 mod 加载即全局解析,但依赖该类的补丁**必须 `loadAfter` 该 mod**。
- **VSE 激情越界 patch**: 改 `.cctor` 数组长度引入 null 空位 → `AllPassions` 遍历破坏、所有激情消失;只改 `PassionToDef` 加边界检查(越界返 `Passions[0]`)。Mono.Cecil patch 栈平衡必须逐路径模拟(分支失败路径残留 `dup` 副本 → `InvalidProgramException`)。
