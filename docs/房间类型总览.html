判定机制（点开：房间到底是怎么被判成某个类型的）

一、能不能判定：引擎在 Room.UpdateRoomStatsAndRole() 里先做门槛检查，只有 room.ProperRoom == true 且 room.RegionCount <= 60 时才计算， 否则统计置空、角色强制为 None（未分类）。

  • ProperRoom = 不触及地图边缘 且 至少有一个 district 的 RegionType == Normal。
  • RegionCount > 60 的超大房间（MaxRegionsToAssignRoomRole = 60）直接放弃判定 —— 巨型基地大厅永远显示"未分类"。

二、怎么判：通过后，遍历 DefDatabase<RoomRoleDef>.AllDefs， 对每个类型调用 worker.GetScore(room)，取分数最高者（MaxBy）。 并列时取 DefDatabase 中靠前的那个，即加载顺序更早的 mod 胜出 —— 卧室/医务室/医疗牢房都是 100000 分，就靠这个裁决。

三、统计怎么算：按 updatePriority 降序执行 —— 优先级 2（财富/空间/美观/清洁）先算 → 1（观感，依赖前四项）→ 0（由曲线派生的隐藏系数，如研究速度、食物中毒）。 跨域取值走 room.GetStat(def.inputStat)。

四、建造预览：GetScoreDeltaIfBuildingPlaced() 在放蓝图时预测类型变化， 所以"再放一张床这里就会变成多人宿舍"这类提示是实时算出来的。

卧室原版 Core
Bedroom
得分100000
判定类 RoomRoleWorker_Bedroom
  • 存在 bed_humanlike + bed_countsForBedroomOrBarracks 的床
  • 任一床为 医疗床 或 囚犯床 → 直接判否
  • 通过 IsBedroom()：①恰好 1 张空床且 0 张有主床 → 是；②0 张空床且恰好 1 张有主床 → 是；③有空床且 >1 张床 → 否
  • 若无成人主人 → 是；若某床主人与其它主人不在同一恋爱簇（非配偶/恋人）→ 否
  • 若有儿童主人，其父母必须都在成人主人列表中，否则 → 否
