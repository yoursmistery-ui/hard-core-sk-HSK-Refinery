## 一、判定机制

**1）门槛**：`Room.UpdateRoomStatsAndRole()` 中，只有 `room.ProperRoom == true` 且
`room.RegionCount <= 60` 才计算，否则统计置空、角色强制为 `None`（未分类）。

- `ProperRoom` = 不触及地图边缘 **且** 至少有一个 district 的 `RegionType == Normal`
- 超过 60 个 region 的超大房间**永远显示"未分类"**，这是硬编码的 `MaxRegionsToAssignRoomRole = 60`

**2）裁决**：遍历 `DefDatabase<RoomRoleDef>.AllDefs`，对每个调用 `worker.GetScore(room)`，
取**分数最高者**（`MaxBy`）。**并列时取 DefDatabase 中靠前者**，即 mod 加载顺序早的胜出
——卧室 / 医务室 / 医疗牢房同为 100000 分，就靠这个裁决。

**3）统计计算顺序**：按 `updatePriority` 降序。优先级 2（财富/空间/美观/清洁）先算 →
1（观感，依赖前四项）→ 0（曲线派生的隐藏系数，如研究速度、食物中毒）。

**4）建造预览**：`GetScoreDeltaIfBuildingPlaced()` 在放蓝图时预测类型变化，
"再放一张床这里就变成多人宿舍"这类提示是实时算出来的。

## 四、附：本次汉化修复（2026-08-29）

整理过程中发现汉化大面积静默失效，已一并修复。

**根因**：`Verse/DefInjectionPackage.cs` 的 `CheckErrors()` 中有
`if (!key.Contains('.'))` 的硬校验，key 即 `LanguageData` 直接子元素的元素名。
因此 **1.6 唯一有效的写法是平铺点号格式**：

```xml
<LanguageData>
  <Bedroom.label>卧室</Bedroom.label>
</LanguageData>
```

以下两种写法都会被拒（`Key lacks a dot` / `has elements which are not 'li'`）并**静默失效**：

```xml
<LanguageData><Bedroom><label>卧室</label></Bedroom></LanguageData>          <!-- 缺层 -->
<LanguageData><RoomRoleDef><Bedroom><label>卧室</label></Bedroom></RoomRoleDef></LanguageData>  <!-- 三层 -->
```

**修复规模**：失效 17636 条 → 108 条（修复率 99.4%），有效条目 246759 → 282488（+35729，零丢失），
双 BOM 文件 395 → 0，解析失败 0，`\r\r` 换行事故 0。改动 2720 个文件，已双目录同步。

**剩余 108 条**：均为深层嵌套结构（如 `corePart.parts.left_lung.customLabel`），
自动生成 key 需理解列表索引规则，风险高，未自动处理，保留原状待人工确认。

**附带发现**：工作区 `1.6hsk附属mod汉化` 原本只有 `1.4` 目录、缺整个 `1.6`，
双目录实为断裂状态；本次已把 1444 个 1.6 文件回传到工作区。
另 `1.6HSK核心全ai汉化` 只存在于部署目录，未纳入工作区。
