1 新流程（只到金属锭）

熔炼  金属原料(矿石/粗铁/废件) + 助熔/焦炭 + 空坩埚  →  熔融坩埚[该金属] + 炉渣
浇锭  熔融坩埚 + 锭模                              →  该金属锭 + 空坩埚(返还)
下游  现有全部配方不变——工具/装备/组件继续吃锭

坩埚与锭模都可复用（配方里"消耗 1 + 返还 1"，净零、无随机）。它们的角色是产能节拍与前置投入：手里几个坩埚就能同时开几炉，不用引入数值池就有了"容器"手感。

2 关键技术结论（修正 v1）

熔融金属必须"每金属一个 def"，不能用 stuff 复用同一个 def。两个硬理由：

  1. RecipeDef.products 的产物 def 是固定列表——stuff 只能改变"产物本身由什么材料构成"，不能让同一个"锭"产物按投入变成 青铜锭／坩埚钢锭 这类不同 def
  2. ThingFilter 没有"按 stuff 过滤"的能力，浇注配方无法写成"只吃青铜的熔融坩埚"

→ 规模：物品数 = 金属种数，配方数 = 金属种数 × 2（熔炼 + 浇锭），外加坩埚/锭模 2 个载体与 2~3 条制模配方。首批建议 7 种：生铁、熟铁、泡钢、坩埚钢、锻钢、青铜、黄铜（乌兹与超级合金留后续）。合计约 7 物品 + 14 配方 + 3 载体配方，量级可控。

3 v1 的"配方数 = 形状 × 2"作废

那是"每种形状都能用任意金属浇"前提下的算法。现在形状只剩"锭"一种，直接按金属数展开更清楚，也不需要 stuff 沿链传递。v1 里"工具头带 stuff、成品工具染色"的整段推演一并作废。
