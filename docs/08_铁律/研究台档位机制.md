# 研究台档位机制(HSK 整合)

> 来源: AGENTS.md §5 研究台要求(2026-08-23 用户修订为六档)。任何涉及"某科技需要什么研究台才能研究"的操作,先查本节再动手。

## 1. 六档研究台对照
| 时代档 | 研究台建筑 | 抽象基类 | 备注 |
|---|---|---|---|
| 原始(Neolithic) | `PrimitiveResearchBench` 原始科技研究台 | PrimitiveBase | Core_SK 提供 |
| 中世纪(Medieval) | `SimpleResearchBench` 基础研究台 | MedievalBase | 中世纪档 |
| 前工业(电力→石化前) | `LabTerminal` 研究终端 | IndustrialBase = 基础研究台+研究终端设施 | 需设施 |
| 后工业(石化→太空前) | `HiTechResearchBench` 高级研究台 | HitechBase = 高级研究台+研究终端设施 | 需设施 |
| 太空(Spacer) | `MultiAnalyzer` 多元分析仪 | HitechMultiBase = 高级研究台+研究终端+多元分析仪 | 需设施 |
| 极致(Ultra) | `LabStation` 实验室工作站 | HitechLabStationBase = +实验室工作站 | 需设施 |

> `LabTerminal`(研究终端)/`LabStation`(实验室工作站)为 Core_SK 提供;`PrimitiveResearchBench`/`SimpleResearchBench`/`HiTechResearchBench`/`MultiAnalyzer` 为游戏本体或 Core_SK。

## 1b. ⚠️ 上表"研究台建筑"列 ≠ 都能写进 `requiredResearchBuilding`(2026-08-27 美狐事故复盘)

上表按**档位**列代表性建筑,但**只有 `thingClass=Building_ResearchBench` 的三个可当研究台写**:

| 建筑 | thingClass | 角色 |
|---|---|---|
| `PrimitiveResearchBench` / `SimpleResearchBench` / `HiTechResearchBench` | `Building_ResearchBench` | ✅ 研究台 |
| `LabTerminal` / `LabStation` | `SK.Building_Lamp`(`ParentName=FacilitiesBase`) | ❌ **设施** |
| `MultiAnalyzer` | 设施 | ❌ **设施** |

> 出处:`Core_SK/Defs/ThingDefs_Buildings/Buildings_Misc_Research.xml` 与 `Core_SK/Defs/ResearchProjectDefs/Research_Abstract.xml`——六个抽象基类一律 `requiredResearchBuilding` ∈ 前三,`LabTerminal`/`MultiAnalyzer`/`LabStation` 全部走 `requiredResearchFacilities`。

**把设施写进 `requiredResearchBuilding`** → 原版 `ResearchProjectDef.CanBeResearchedAt` 首行
`if (requiredResearchBuilding != null && bench.def != requiredResearchBuilding) return false;`
对任何研究台恒 false,ResearchTreeSK `Node.PlayerHasAnyAppropriateResearchBench`(`requiredResearchBuilding != null` 时转调原版)也恒 false
→ **该节点"没有任何研究台可以点击",日志零报错、纯静默**。
实例:美狐 `Miho_Celestial` 曾被适配补丁改成 `requiredResearchBuilding=LabStation` 而卡死;极致档正确写法 = 台 `HiTechResearchBench` + 设施 `LabStation`(对照 `HitechLabStationBase`)。

**反向缺陷:`requiredResearchBuilding` 整个留空** → 原版视为"任意研究台皆可",绕过六档门槛。
同类实例:`Fabrication`(`鼠族HSK拓展/Patches/99_研究台门槛修复.xml`)。第三方 mod 的研究页签常整批留空(美狐 23 节点里 10 个留空),适配时须逐节点补齐。

## 2. 机制坑(光写 requiredResearchBuilding 不够)
- 反编译确认: Core_SK 的 `SK.Patch_ResearchProjectDef_CanBeResearchedAt` Postfix 以 **`SK.AdvancedResearchExtension.requiredResearchBuildings`**(DefModExtension)列表为准放行研究台。
- **精确语义**(勿记反):Postfix 首行 `if (__result || !HasModExtension<AdvancedResearchExtension>()) return;` —— 它**只能把 false 救成 true,不会把 true 改成 false**。所以缺该扩展**不会报错、也不会被拒绝**,只是"可接受的研究台集合"退化成 `requiredResearchBuilding` 那一个;而 Core_SK 基类是靠这个列表放宽的。
- 继承 `MedievalBase`/`IndustrialBase` 的节点,该列表 = `[基础研究台, 高级研究台]`,所以中世纪/前工业档"天然满足";其它档须显式加入。

## 3. 标准写法
研究节点须同时:
1. Add `<requiredResearchBuilding>X</requiredResearchBuilding>`(X = 上表对应建筑,且**必须是 §1b 的三个真研究台之一**)
2. Add `<modExtensions Inherit="False">` 重写 SK 扩展列表(保留 `<li Class="ResearchTreeSK.ResearchTreeSKModExtension" />`),把硬门槛列表改成仅当前档所需建筑(如后工业档覆盖为仅 `HiTechResearchBench`)。
3. 设施走原版 `requiredResearchFacilities`(`LabTerminal`/`MultiAnalyzer`/`LabStation`)。

> ⚠️ **例外:依赖 ResearchTreeSK 自动排布的页签不要加 `ResearchTreeSKModExtension`。** 加了会保留 XML `researchViewX/Y`,而 ResearchTreeSK 的坐标查重(`PopulateNodes`)**不分页签**,会与 Core_SK 各页签的固定坐标撞车并报 `HardcoreSK research ... have the same position`,前置被自动排布后还会触发 "not positioned to the right"。第三方 mod(美狐等)整页签走自动排布时,只加 `SK.AdvancedResearchExtension`、不加 `ResearchTreeSKModExtension`。

> 实例: 工业工具II(`RKHSK_Tools_Industrial2`)按后工业档设 `HiTechResearchBench`+终端设施,覆盖列表为仅 HiTech;中世纪工具继承 `MedievalBase`、工业工具I 继承 `IndustrialBase` 即分别满足。
> 实例: 美狐 23 节点全部按 §1b/§3 补齐门槛(`美狐HSK拓展/HSK_1.6/Patches/ResearchProjectDefs/Miho_ResearchBench.xml`),统一不加 `ResearchTreeSKModExtension`。
