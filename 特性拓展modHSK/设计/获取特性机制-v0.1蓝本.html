0. 总体架构

引擎名为 CausalTraitHub(因果特质枢纽),底部有一个全局节流账本统管所有"动态特性"的获得与失效(通用底层机制,不分来源)。它接管原有的"成长时刻"分发,让特性获得从"纯随机抽奖"变成"有因果、有节奏、有戏剧"。

特性来源(三路并行)
  ① 成长时刻(原版,保留加权)      —— 由 BetterGrowthMomentTraits 增强
  ② 背景强关联·叙事者事件(机制一) —— 每≥2年,据背景→特质池,随机授予
  ③ 生活习惯·行为计数(机制二)     —— 行为累积越阈值,据因果授予/翻转
                      └─ 全部汇入「CausalTraitHub 全局账本」节流/容量/戏剧反馈

★ 底层节流账本(通用·不分来源)

  • 获得:每名殖民者 每 2 年最多获得 1 个动态特性(跨①/②/③累计)。
  • 失效:每名殖民者 每 5 年最多失效 1 个动态特性(跨来源累计)。
  • 容量:动态特性总数 ≤ 特质槽 mod(More Trait Slots)提供的特性槽上限 —— 由该 mod 决定殖民地/殖民者可容纳多少特性,CausalTraitHub 只在其余量内授予,不设自己的硬编码上限。

一、机制一:背景强关联 · 叙事者事件注入

1.1 触发与节奏

  • 用一个叙事者事件(IncidentDef) RK_TraitGrantingEvent,最小重燃间隔(MinRefireDays)= 730 天(2 年)。
  • baseChance 设为低频(如 0.035~0.05),并受叙事者阶段影响,保证"罕见但不缺席"。
  • 事件弹出时从全殖民地筛选符合资格者;满足条件则授予,否则事件静默跳过(记日志,等待下一窗口)。

1.2 候选者的硬性资格(全部满足才可见)

规则 说明
加入年限 入队时刻距今 > 2 年
上次授予冷却 距今上次从"本系统获得动态特性" ≥ 2 年
身份 非囚犯、非机械体、非昏迷/老人死期,有活跃思维者
容量 当前动态特性数 < 特质槽 mod 所允许上限(全局账本判定)

1.3 背景→人格域→特质池 强关联(核心规则)

第①步·背景画像:取背景的 skillGains 中最大值技能域作为该背景的「人格域」。背景最高技能 = 人格域(战斗/社交/信仰/情爱/工作/生活/身体/灵能)。

第②步·人格域→特质池:按背景表配的 关联经历 从特性总表取候选。每域一张候选池(见 CSV 规则-背景关联特质池.csv),池内每条记录含 候选特质 + 关联强度权重。

第③步·强关联权重(技能×特质耦合):

权重 = 候选特质本身与背景技能域相符的基础权重
       + 若背景最高技能域 == 特质效果所依赖的技能域, 权重 × 2(强耦合)
       − 若特质与背景 forcedTraits 冲突, 移出池

例:背景为"神射手"(Shooting 高)→ 人格域=战斗 → 池内含射击类特质;若特质效果增强射击,耦合 ×2 → 神射手小人更易获得战斗/射击类性格。

第④步·抽取:在候选池内按权重随机器抽 1 个授予。

1.4 授予后

  • 立即弹 Letter(戏剧反馈):说明"基于其过往(背景),小人在殖民地的这些岁月里沉淀出 XX 性格",给出该特质的描述。
  • 记入「授予账本」:pawnId, defName, 授予日(用于 2 年节流)。
  • 若造成能力溢出或与后续冲突,交由统一冲突消解(见 §4)。

1.5 失效机制(特性会退场)

本小节是全局底层节流账本中"失效"分路的落地,不仅机制一,机制二获得的动态特性同样受此五年龄计约束。 - 触发:叙事者事件 RK_TraitRevocationEvent,MinRefireDays = 1825 天(5 年)。 - 上限:该次最多从全部动态获得的特质中移除 1 个(受全局 5 年≤1 约束)。 - 移除优先级(人造"性格漂移"): 1. 已与本小人当前习惯(机制二反向统计)最不符的动态特质; 2. 否则移除获得最早的动态特质。 - 移除同样记账本、弹 Letter("X 的性格日渐淡去了…")。 - 永不移除:生成时自带/背景强制/forcedTraits 特制,以及尚在 2 年冷却期内的新获动态特质。

二、机制二:生活习惯强相关 · 行为计数

2.1 架构

给每个殖民者维护一组行为计数器(CausalTraitHub 内 Dictionary>)。行为来源由 Harmony 挂钩: - 工作:Pawn_JobTracker.EndCurrentJob 按 JobDef / WorkTags 计数(园艺=PlantWork, 屠宰=ButcherCorpse, 搬运/建造/医疗…)。 - 娱乐:JoyGiver / RecreationDef(看电视=JoyKind 'Television', 阅读=Book, 网游…)。 - 战斗:Verb_MeleeAttack / 击杀(ThingDied 且 attacker=pawn)。 - 社交:Pawn_SocialMemoryManager / 交谈、换伴侣、lovin'(已有的关联)。 - 灵能/信仰:祷告、仪式(祭司系统联动)。

2.2 计数器的"正/负/方向"

  • 正向:做得好 → 累积正分(如园艺完成了成熟作物 → 绿拇指倾向)。
  • 负向:做得糟 → 累积负分(如园艺作物坏死次数多 → 黑手倾向)。
  • 数值用于阈值判定,不是一个开关,而是渐变档位(见 2.3)。

2.3 阈值与授予规则(大规则表)

每条 行为维度 规则: | 字段 | 含义 | |------|------| | dataSource | 计数数据源(JobDef/WorkTag/JoyKind/击杀) | | 正向阈值 | 累积正分越线 → 授予正向特性 | | 负向阈值 | 累积负分越线 → 授予负向特性 | | cooldown | 该维度授予后冷却(默认 183 天) | | 冲突 | 正/负互斥、与已有特质冲突则跳过 |

2.4 戏剧反馈

  • 授予即刻弹 Letter + 心情变化(小人有意识感受到自己性格的变化,±2 心情,视正负)。
  • 翻转场景(如"园艺能手"变"园艺不通")弹更强反馈。

三、两条机制与原有系统协同

  • 容量:动态特性总数受 More Trait Slots 扩容数量限制,默认动态特性上限 2(可配);达到上限则机制一/二暂不授予,只继续累积计数器/账本。
  • 与成长时刻:机制二授予后,同一维度(如园艺)短时间内不再被成长时刻重复给同类。
  • 冲突消解:草拟为"先到先得"或权重择优——本小节统一定义,见下方 §3.2 特性冲突。

3.2 特性冲突(创建与授予时强制)

边界(你已明确):已存在的小人一律不动。冲突只在两处生效——新建人物 与 动态授予/成长时刻新增特性。

  • 底板双保险: 1. 原生层:各 TraitDef 的 <conflictingTraits> 内建互斥,游戏新建人物时自动排歧、且授予新特质时自动移除旧特质; 2. 兜底层:本 hub 自备一张全局冲突表 <表/规则-特性冲突.csv>,为跨 mod 组合(原生声明可能漏)与自定义 HSK_* 特质补声明,并在授予前做一次独立校验。
  • 判点(全部走统一的"可否并存"检查):
  • 新建人物:随机选特质时,若同一池内两特质互斥 → 二选一,保留权重/概率高者,绝不共存;
  • 动态授予(机制一/二)+ 成长时刻:候选特质与小人已有特质冲突 → 拒绝本次授予(绝不清除/替换已存在特质)。
  • 数据驱动:所有互斥对以 <表/规则-特性冲突.csv> 为唯一数据源;目标 HSK_* 特质定义时把冲突直接写进自身 <conflictingTraits>,跨 mod 的对用 XML 补丁双向加装。该表含三级来源,由 Source/gen_conflict_table.py 生成: 1. 原生内建(178 组):六数据源 TraitDef 已声明,游戏本就强制,无需改; 2. HSK_ 自定义(9 组):新建特质自身互斥,写入 TraitDef; 3. 补充语义(15 组):遍历全特性发现的跨 mod 语义对立(如 挑刺↔邋遢、沉眠↔浅眠、善良↔嗜血、孤僻↔外向、冷热交叉等),向双方双向加装 + 生成期兜底校验。
  • 已有小人不受影响:不改动历史小人身上的任何特性;新增冲突规则只对未来"新增"生效。
