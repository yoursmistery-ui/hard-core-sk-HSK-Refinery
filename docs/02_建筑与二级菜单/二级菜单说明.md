# 二级菜单(ArchitectSense 子分类)说明 —— 什么是二级菜单?

> 关联: AGENTS.md §7。本文档为详细版,AGENTS.md 只保留一行链接。
> 参照实现: 鼠族家具拓展 `Defs/SubCategories_RatkinStructure.xml`、酒馆工具整合HSK `Defs/DesignationSubCategoryDefs/`。

## 什么是二级菜单(先看这个)

**二级菜单 = 建筑师菜单(Architect)里,一级分类(如「家具」「结构」「生产」)下面再折叠出的小分类。**

- **一级分类**(designationCategory): 建筑师菜单顶部的 家具/结构/生产/杂项/电力…,建筑靠 `<designationCategory>Furniture</designationCategory>` 进入。
- **二级菜单**(DesignationSubCategoryDef): 点开一级分类后,建筑按功能再分组折叠(如「座椅」「桌台」「床铺」),由 **ArchitectSense** 的 `ArchitectSense.DesignationSubCategoryDef` 定义。**没有二级菜单 = 建筑全挤在一级分类里,不分组。**

> ⚠️ ArchitectSense 功能由 **HSK 内置 `Core_SK\Assemblies\ArchitectSense.dll`** 提供,**不需要单独装 ArchitectSense mod**。只要写了 `ArchitectSense.DesignationSubCategoryDef`,游戏就有二级菜单。

## 机制

1. 建筑 ThingDef 必须有一级分类(`designationCategory`,继承基类也算);
2. 新建 `ArchitectSense.DesignationSubCategoryDef`,把建筑 defName 写进它的 `<defNames>` 列表 → 建筑自动归入该二级菜单;
3. **子分类的 `designationCategory` 必须与建筑的一级分类一致**(家具→Furniture/结构→Structure/生产→Production/辅助→Accessories),否则不显示。

## 写法模板

```xml
<ArchitectSense.DesignationSubCategoryDef>
    <defName>XX_SubCategory_Seats</defName>              <!-- 子分类唯一ID -->
    <label>tavern seats</label>                          <!-- 英文名(中文由汉化覆盖) -->
    <description>...</description>
    <defNames>                                           <!-- 归入本子分类的建筑 defName 列表 -->
        <li>Tav_ChairA</li>
        <li>Tav_SoftChair</li>
    </defNames>
    <designationCategory>Furniture</designationCategory> <!-- 必须与建筑一级分类一致! -->
    <debug>false</debug>
    <order>10</order>                                    <!-- 子分类显示顺序(越小越前) -->
    <types>                                              <!-- 可选: ArchitectSense 过滤类型 -->
        <li>Seats</li>
    </types>
</ArchitectSense.DesignationSubCategoryDef>
```

## 要点(踩坑)

- 汉化目录必须 `Languages\ChineseSimplified (简体中文)\DefInjected\ArchitectSense.DesignationSubCategoryDef\`(**带后缀!**),汉化文件里 defName 必须与上面一致。
- 文件放 `Defs\` 下任意子目录都会被递归扫描(酒馆放 `Defs\DesignationSubCategoryDefs\`)。
- 建筑本身**没有 designationCategory 就进不了建筑师菜单**,二级菜单自然也没有——先查建筑的一级分类,再写子分类。
- **结构建筑(柱子/门)也必须建子分类**,否则结构分类下不分组(酒馆 2026-08-21 已补: 柱子/门)。

## 酒馆已整合的二级菜单(2026-08-21 现状)

- 家具: Seats 座椅 / Tables 桌台 / CounterRack 柜台货架 / Beds 床铺 / BedroomStorage 卧室储物
- 辅助: Lights 照明 / DecorRugs 装饰地毯
- 生产: Kitchen 厨房
- 结构: **Columns 柱子 / Doors 门**(新建)
- 定义文件: `Defs\DesignationSubCategoryDefs\SubCategories_Tavern.xml`(家具/辅助/生产)+ `SubCategories_TavernStructure.xml`(结构);汉化同名文件在带后缀汉化目录。

## 用别的 mod 的子分类(2026-09-10 冰柜实例)

`SubCategory_*` 大多由 **Core_SK** 定义(`Core_SK/Defs/DesignationSubCategoryDefs/SubCategories_*.xml`)。
想把自建建筑塞进现成子菜单(如「存储 › 冷藏」= `SubCategory_Refrigerators`)时:

- **写补丁,别改对方 def**。往 `<defNames>` 追加 `<li>本件defName</li>` 即可,套 `PatchOperationConditional` 存在性门控
  (1.6 起 Operation 级 `MayRequire` 已失效);目标 def 由 Core_SK 提供,本 mod `loadAfter skyarkhangel.HSK`,执行时必然存在。
  实例: `HSK工业科研大修/Patches/A6_冰柜入存储冷藏.xml`。
- **子分类的 `defNames` 允许收录"别的一级分类"的件**: `sbz_Fridge` 自身 `designationCategory=Temperature`,
  照样出现在「存储(ASFstorage)› 冷藏」里。所以只加 defName 就能进子菜单,**不必**为了它去改件的一级分类。
  (冰柜为语义干净仍把一级分类从 `Temperature` 改成了 `ASFstorage`,但不是进子菜单的必要条件。)
- 一级分类值以**运行时终态**为准: 存储分类的 defName 是 `ASFstorage`(中文「存储」),
  ASF 自带补丁里的 `LWM_DS_Storage` 在本机不会生效(`Unified.xml` 里 0 次)。
- 子分类是否有**二级菜单条**取决于 ArchitectSense(`Core_SK/Assemblies/ArchitectSense.dll`),它有 `order`/`types` 字段。
