## 1 五项改动

### 1.1 炉衬耗材 + 进度条（替代耐久度）✅ 纯 XML

反编译 `RimWorld.CompProperties_Refuelable` 确认字段可用：`fuelCapacity`、`fuelConsumptionRate`（`ConsumptionRatePerTick = rate/60000`，按**游戏日**标定）、`consumeFuelOnlyWhenUsed`、`fuelFilter`、`minimumFueledThreshold`、`drawFuelGaugeInMap`、`drawOutOfFuelOverlay`、`canEjectFuel`。

- **进度条 = 炉衬余量，会随使用下降**：`fuelFilter` 只放 `RK_Met_Firebrick`，小人自动搬耐火砖去"补炉衬"（原生 refuel job，无需代码）
- 参数：`consumeFuelOnlyWhenUsed=true`、`drawFuelGaugeInMap=true`、`initialFuelPercent=100`、`tickerType=Normal`
- 烧穿的替代表现：炉衬低于 `minimumFueledThreshold` → 熄火 + 原生 OutOfFuel 覆盖层 + 停产（不炸、不刷火灾，避免"堆数量轮流用"反模式）
- 语义说明：搬进炉的耐火砖会被转成数值（`Refuel()` 里 `Destroy()`），即"砌进炉衬"，符合直觉

> 对照：你原话的"积渣条涨满→清废物"也能纯 XML 做（`fuelFilter=矿渣` + `canEjectFuel=true`，条满后用 gizmo"排出"取回实物）。缺点：**EjectFuel 一次全排空**、取 `fuelFilter.AllowedThingDefs.First()`（filter 只能一种物）、**清渣需玩家手点**，且被搬进渣坑的矿渣会从世界里消失。故推荐炉衬型；积渣型作可选项保留（见 §5 Q1）。

### 1.2 矿渣副产物 ✅ 纯 XML

- `RecipeDef` 的 `<products>` **原生支持多产物**，不需要 ProcessorFramework
- 严禁为此新建 `ProcessDef`：本环境那颗融合版 `ProcessorFramework.dll` 的 `thingDef` 是运行时 `ActiveProcess` 型，原版多产物写法会反序列化失败 → 整 def 不加载 + 建筑 processes 交叉引用报错
- 产渣量随品位：贫矿多、富矿少（写进各配方 `products`，静态可预期）
- 三条下游（闭环）：① 矿渣砖/矿渣水泥 → 建筑；② 回收残余铁 → 复用环境已有先例 `ExtractMetalFromSlag`；③ 回填/铺地
- 渣保持**实物**状态：落地/进库存，才能进下游配方

### 1.3 高炉温度 ✅ 纯 XML（显示 + 真实热代价）

- 显示：新建 `StatDef` `RK_Met_FurnaceTemp`（`unit=Celsius`），各炉在 `statBases` 写定值（炼铁炉 1250 / 高炉 1500 / 坩埚 1600 / 电弧 3000…）
- 代价：`SK.CompProperties_HeatPusherAdvanced`（Core_SK 现成，Odyssey 建筑用到 `heatPushMaxTemperature=250`）→ 炉周房间升温，**原生**带来小人热射病/灼伤、食物腐坏加速、舒适度崩
- 硬门禁的真相：原版 `RecipeDef` 读不到建筑 stat，所以"谁能炼什么"仍由**配方挂在哪座炉**决定。温度提供的是叙事 + 热环境代价（布局惩罚：高炉要远离生活区/食品区），不是新校验器
- 若要"温度决定产物档位"，做法是**拆多座同级炉**（高炉 I/II/III），不是给单座炉加动态温度判定

### 1.4 耐火材料门禁 ✅ 纯 XML

- 新 `ThingDef` `RK_Met_Firebrick` 耐火砖：软粘土 `SoftClay` + `ChunkLimestone`/`CrushedStone` 在 `Kiln` 烧制，挂 `Ceramics_A1 → Ceramics_B1` 线（正好给你要的"耐火材料科技攀升"当入口）
- 落位法：**追加 `costList`**（推荐，固定不可替换）。不改 `stuffCategories`——`TableFurnace` 现在是 `Stony|Bricks × 240`，改成专用 stuff 类别会引入颜色遮罩、并且把所有同类可塑建筑一起拖下水
- 改造范围：`TableFurnace`、`Bloomery`、`Finery`、`Kiln` 四座（现有 `costList` 保留，只追加耐火砖）
- 新增建筑必须补 `uiIconPath` 且指向**真实单张 png**（stuffable 缺 uiIcon → 点选时每帧 NRE 表现为"一点就卡死"）；现有三座的 `uiIconPath` 已存在，只有 `Kiln`/新增件要查
- 同步排查 `HSK修复整合` 的去木板/`stuffCategories` 相关补丁会不会打空报红 → 需要就套 `PatchOperationConditional` 存在性门控

### 1.5 钢体系归一 ⚠ 影响面最大，放最后

> 逐配方的终态核对表与可执行删改清单已外挂 → `TFC冶铁链统一改造清单_20260830.md`（同目录）。本节只留判定与手法。

现状乱点（已核）：

1. `PigIron` 生铁 与 `CastIron` 铸铁 —— 同物两名，都在高炉/铸造线上出现
2. 中世纪铁钢五档名称机翻混杂乱：`WroughtIron` 熟铁 / `ForgedSteel` 锻焊钢 / `BlisterSteel` 泡钢 / `CrucibleSteel` 坩埚钢 / `WootzSteel` 乌兹钢，另有"锻造剪切钢"这类异名
3. `SLDBar`/`USLDBar` 类别把熟铁(0.75)与锻钢(1.2)/乌兹(3.0)混进同一过滤池 → CE 弹药金属返还永远取最便宜的熟铁（这是既成事实，改类别会连带改返还）
4. 与 Materials Science 的 `CarbonSteel/SpringSteel/ToolSteel/MildSteel/AR500` 无清晰上下承接

统一四招（全 XML，**defName 一律不动**——1759 条配方交叉引用、本 mod 147 件物品都在消耗 `CarbonSteel/SpringSteel/...`）：

1. 中文 label 重排成一条念得通的阶梯：熟铁 → 锻钢 → 坩埚钢 → 乌兹钢 → 合金钢；机翻异名清理，走附属包路由 `HSK附属mod汉化/1.6/Vile's Metallurgy/...`
2. 每档钢**独立 stuffProps + 独立可用档**（能做什么/不能做什么），把"升级动力"从耐久挪到这里
3. 配方去重：`PigIron` 定为唯一中间物，`CastIron` 标签改成"铸件用料"用途化；`BlisterSteel` 只由渗碳炉产、只被坩埚钢消耗（不当通用钢卖）
4. 研究档对齐 HSK 六档研究台（铁器档 → `PrimitiveResearchBench`/`SimpleResearchBench`，钢 → `LabTerminal`），注意 `SK.AdvancedResearchExtension.requiredResearchBuildings` 是硬门槛

## 2 明确不做

- 随时间磨损的耐久度：RimWorld 建筑自带 `MaxHitPoints` + Repair，再加"用久了坏"只会逼玩家堆数量
- 渣层堆在炉内 / 风口结瘤 / 热风炉格子砖积灰：需要 per-building 累积状态 + `CompTick` + 自建 UI = **DLL 活**，XML 做不到；且受性能铁律约束只能低频轮询。真要做另立方案
