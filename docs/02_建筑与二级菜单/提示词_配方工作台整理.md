## 四、方法论(怎么判断"该在哪个台")

**三种配方挂载机制**(务必区分,写错 xpath 会报错或无效):
1. **手写 RecipeDef + `<recipeUsers>`**: 鼠族/维多利亚大部分装备(01/02/05 号补丁定义,
   名如 `RKHSKFix_Make_*` / `RKHSKVictoria_Make_*`)。改 `recipeUsers/li` 即可。
2. **recipeMaker 自动配方 + `recipeMaker/recipeUsers`**: CE 装备(无线电背包/望远镜)、
   RatkinRaceHSK 基类生成的配方。xpath 用 `ThingDef[...]/recipeMaker/recipeUsers`。
3. **工作台 `<recipes>` 列表**(建筑 ThingDef 直接挂配方): 原版工作台如 TableMachining/
   TableStonecutter。⚠️ 若节点是 `<recipes IsNull="True" />`,必须用 PatchOperationReplace
   整体替换,不能 Add(会报 "Failed to find a node")。
4. **CE AmmoInjector 自动注入**(弹药): CE 弹药配方不走 recipeUsers/recipes,由 CE 代码按弹药
   thingDef 的 tradeTags 决定工作台——`CE_AutoEnableCrafting`(纯)= AmmoBench,
   `CE_AutoEnableCrafting_XXX`(带后缀)= 工作台 defName=XXX(如 `_FabricationBench`=手工装配台)。
   已反编译 CombatExtended.dll 的 AmmoInjector.InjectAmmos 确认。改 CE 弹药工作台 = 改
   thingDef tradeTags,不是 recipeUsers。

**工作台体系(HSK)常识**:
- `RK_ElectricTailoringBench` = 鼠族电动裁缝台(电力);`RK_HandTailoringBench` = 鼠族手动裁缝台。
  普通衣物/制服/背包→这两个;太空护甲/动力甲→HyperTailoringBench(先进纺织,做战斗服/动力甲)。
- `RK_FueledSmithy` / `RK_ElectricSmithy` = 鼠族锻造台(燃料/电力)。中世纪护甲/近战/盾→这里。
- `TableMachining` = 电动机械加工台(切石/拆解机械体/CE 弹药注入)。
- `AmmoBench` = 弹药工作台(CE 普通弹药);`TableHeavyAmmunition` = HSK 重型弹药台。
- `AdvWeaponCraftingWorkTable` = 先进武器加工台(枪械);`MechWeaponCraftingWorkTable` = 机械武器台。
- `HyperTailoringBench` = 先进纺织工作台(太空护甲/动力甲/战斗服)。

**判断原则**: 看产物类型——衣物/背包→裁缝台;护甲/动力甲→先进纺织或锻造台(视材质);
近战武器/中世纪装备→锻造台;枪械→武器加工台;弹药→弹药台;机械体拆解→机械加工台。

## 七、关键坑(务必遵守)

1. **补丁写法铁律**: 一律用平铺 `<Operation Class="PatchOperation...">` 写在 `<Patch>` 下,
   **禁止** `PatchOperationFindMod` + `PatchOperationSequence` 嵌套(1.6 下不生效)。
   条件门控用 `MayRequire="packageId"` 属性(如 `skyarkhangel.HSK` / `CETeam.CombatExtended`)。
2. **Unified.xml 是 UTF-16LE**: `Mods\Unified.xml` 是游戏最终 def 数据库(Unified XML Export 导出,
   UTF-16LE+BOM)。读取必须 `data = open(p,'rb').read().decode('utf-16')`,然后
   `rfind('<ThingDef',0,i)` + `find('</ThingDef>',i)` 切片提取单个 def。直接 grep 会乱码。
3. **IsNull 节点**: 目标节点若是 `<recipes IsNull="True" />` / `<recipeMaker IsNull="True" />`,
   Add 会失败,必须 Replace。
4. **同路径贴图覆盖**: 改贴图路径时注意 Core_SK 与 Vile MS 同路径贴图,后者后加载覆盖
   (详见 AGENTS.md 7.6 节)。
5. **改完必须验证**: `python tmp/verify_26.py`(26 号 xpath 命中)+ 对新增补丁写类似验证脚本,
   确认 xpath 命中 Unified.xml;XML 用 `xml.etree.ElementTree` 解析校验。
6. **双份同步**: 工作区 + 部署目录逐字节一致(cmp 验证)。
7. **MissileGirl 缓存**: 改补丁后若游戏不生效,清
   `...\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\MissileGirl\Cache`。
