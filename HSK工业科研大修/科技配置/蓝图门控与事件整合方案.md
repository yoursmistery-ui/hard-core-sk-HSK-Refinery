## 二、蓝图门控系统设计

### 2.1 核心概念

**需蓝图科技** = 需要蓝图才能开始研究的科技。蓝图只能作用于「需蓝图清单」内的科技；累计 N 张对应时代蓝图后解锁（可开始研究）。

### 2.2 蓝图类型判定（从本 mod 判定）

蓝图物品 4 种，按科技 `techLevel` 自动映射所需蓝图类型：

| 科技 techLevel | 所需蓝图 | 说明 |
|---|---|---|
| Neolithic | TechnologyBlueprintNeolithic | 石器蓝图 |
| Medieval | TechnologyBlueprintMedieval | 中世纪蓝图 |
| Industrial | TechnologyBlueprintIndustrial | 工业蓝图 |
| Spacer | TechnologyBlueprintSpacer | 太空蓝图 |
| Ultra | TechnologyBlueprintSpacer | 无 Ultra 蓝图，用最高档太空蓝图 |
| Archotech | TechnologyBlueprintSpacer | 无 Archotech 蓝图，用最高档太空蓝图 |

**判定逻辑**（写入 BlueprintUnlockHSK.dll）：
1. 蓝图使用前，读取蓝图 comp `CompBlueprintTech.techLevels`（该蓝图可作用的时代）。
2. 读取目标科技 `techLevel`，映射到所需蓝图时代（上表）。
3. 蓝图时代与目标科技映射时代**必须匹配**，否则提示"蓝图时代不符"且不消耗蓝图。
4. 支持每节点覆盖（见 2.4 配置表）。

### 2.3 门控机制（沿用 3 次解锁制）

| 参数 | 当前值 | 建议 |
|---|---|---|
| 解锁所需蓝图数 | 3 | 3（可配置） |
| 每次使用科研点 | +500 | 500（可配置） |
| 蓝图时代匹配 | 未实现 | 必须匹配（本次新增） |
| 解锁状态保存 | WorldComponent | 保留 |
| 已解锁科技可开始研究 | CanStartNow=true | 保留 |

**流程**：
1. 使用蓝图 → 检查目标科技在清单内且未完成未解锁 → 检查蓝图时代匹配。
2. 匹配 → 目标科技 +500 科研点，累计使用次数。
3. 累计 3 张 → 解锁（CanStartNow 返回 true，前置视为满足）。
4. 不匹配 → 提示时代不符，不消耗蓝图。

### 2.4 需蓝图清单（TargetTechs 配置表）

清单由 DLL 内 `TargetTechs` 列表维护（当前 8 个，见第四节扩展）。每个条目可带时代覆盖（默认按 techLevel 自动判定）。

## 六·五、v2 升级设计（2026-08-23 用户需求：一一对应蓝图 + 存储科研进度 + 前置判定 + 科研树 UI）

> 用户新增需求（覆盖 2.1-2.4 旧设计）：
> 1. 蓝图做配置，一个蓝图**一一对应**一个科技节点；
> 2. 已研究过的科技，其蓝图点击应用后把科研值**存储**起来（科研进度银行）；
> 3. 科研树界面展示存储了多少科研进度（UI）；
> 4. 所有蓝图使用前必须**解锁到前一级**（前置科技已研究，判定类似 CanStartNow）才能用，否则不能解锁。

### 6.5.1 数据模型（DefModExtension，配置即 Defs，用户可改）

**① 科技节点侧 `BlueprintGateExtension`**（挂在需蓝图科技的 ResearchProjectDef 上）：

```xml
<ResearchProjectDef>
  <defName>Melee_Archotech</defName>
  <modExtensions>
    <li Class="BlueprintUnlockHSK.BlueprintGateExtension">
      <blueprintDef>Blueprint_Melee_Archotech</blueprintDef>  <!-- 对应蓝图物品 -->
      <researchPoints>500</researchPoints>                    <!-- 每张蓝图科研值 -->
      <unlockCount>3</unlockCount>                            <!-- 解锁需张数 -->
    </li>
  </modExtensions>
</ResearchProjectDef>
```

**② 蓝图物品侧 `BlueprintTargetExtension`**（挂在蓝图 ThingDef 上，一一对应）：

```xml
<ThingDef ParentName="BlueprintHSK_Base">
  <defName>Blueprint_Melee_Archotech</defName>
  <label>蓝图：近战武器 VII</label>
  <modExtensions>
    <li Class="BlueprintUnlockHSK.BlueprintTargetExtension">
      <targetTech>Melee_Archotech</targetTech>
    </li>
  </modExtensions>
</ThingDef>
```

**③ 配置表**：`科技配置/BlueprintConfig.xml`（人类可读清单，供维护/核对，DLL 实际以 DefModExtension 为准）。

### 6.5.2 蓝图使用逻辑（DLL 重写）

使用蓝图 `Blueprint_X`（targetTech = X）：

| 步骤 | 判定 | 结果 |
|---|---|---|
| 1 | 前置判定：X 的全部 prerequisites 是否已研究（类似 CanStartNow，但不含蓝图自身） | 未研究 → 提示"前置科技未研究"，**不消耗** |
| 2 | X 是否已完成（IsFinished） | 已完成 → 科研值存入**存储池**（storedPoints），提示"已研究，科研进度已存储"，消耗 |
| 3 | X 未完成 | +researchPoints 到 X 进度，useCount++ |
| 4 | useCount >= unlockCount | X 解锁（CanStartNow=true），提示"科技已解锁" |
| 5 | 未达解锁数 | 提示"蓝图应用 (n/unlockCount)" |

### 6.5.3 存储科研进度（科研进度银行）

- Tracker 新增 `storedPoints`（float，随存档保存）。
- 已研究科技的蓝图 → 科研值进存储池。
- 存储池可在科研树 UI 一键应用到**当前研究项目**（抵扣剩余进度）。
- 存储池也可在 UI 手动分配到任意可研究科技（可选，二期）。

### 6.5.4 科研树 UI（ResearchTreeSK 挂载）

- Harmony 手动 Patch `ResearchTreeSK.MainTabWindow_ResearchTree.DoWindowContents`（Postfix，画右上角面板）：
  - 显示存储科研进度（storedPoints）；
  - 按钮「应用存储进度到当前研究」；
  - 列出全部蓝图门控科技及解锁状态（n/unlockCount，已完成标绿）。
- 兜底：ResearchTreeSK 未装时 Patch 原版 `MainTabWindow_Research.DoWindowContents`。
- 挂载方式：静态构造器里 `AccessTools.TypeByName` 探测 → 存在才 Patch（避免 PatchAll 抛错）。

### 6.5.5 蓝图物品（一一对应，每门控科技一张）

- 新增基类 `BlueprintHSK_Base`（复用 TBnRE 的 CompUsable + CompUseEffect_UnlockTechnology）。
- 每个门控科技一个 `Blueprint_<TechDefName>` ThingDef，自带 BlueprintTargetExtension。
- 原 4 个时代蓝图（Neolithic/Medieval/Industrial/Spacer）**保留**，继续用于逆向工程/自制出售机制（随机科研进度，不参与门控）。

## 七、风险与注意

1. **自制蓝图研究死锁风险**：原版 `ResearchProjects_Blueprints.xml` 带 `CompleteTechLevelPrereq`（需完成整个时代才可研究自制蓝图）。若蓝图门控科技在该时代内，会形成死锁（无法完成时代 → 无法自制蓝图 → 无法解锁门控科技）。**建议**：移除 Spacer 自制蓝图研究的 `CompleteTechLevelPrereq`，或让门控科技不计入时代完成度。
2. **ResearchTreeSK 兼容**：新增 `Blueprints` 研究 tab 需确认与 ResearchTreeSK 无坐标冲突；自制蓝图研究可考虑并入现有 tab（如 Craft_SK）。
3. **蓝图时代匹配**：Ultra/Archotech 无专属蓝图，统一用太空蓝图，需在 UI 提示"最高档蓝图"。
4. **事件补丁目标存在性**：RimQuest/GoExplore/Cybranian 的补丁须用 xpath 存在性门控（PatchOperationConditional），未装对应 mod 时整段跳过（1.6 Operation 级 MayRequire 已失效）。
5. **汉化铁律**：DefInjected 根节点必须 `<LanguageData>`，defName 作节点名；文件夹名必须 `ChineseSimplified (简体中文)`（带后缀）。
