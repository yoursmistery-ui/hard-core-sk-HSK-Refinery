# 外政数据结构与挂钩点 · 附录

> 立档 2026-09-01。性质：**实现参考，未编码**。承接 [`外政与任务大修重构_架构设计方案.md`](./外政与任务大修重构_架构设计方案.md)，沉淀 BOTR 可挂钩面、任务大修补丁点、帝国从属建模与宗主候选清单。类名均 `BordersOfTheRim.` 前缀；来源反编译 `_tmp/_botr_decompile/BordersOfTheRim.decompiled.cs`。

## 0. 底座架构定调（决定所有挂钩方式）

- BOTR **单一状态中枢** = `WorldComponent_Territories : WorldComponent`；**无 GameComponent/MapComponent/FactionDef modExtension**，全部派系态以 `faction.loadID`/`settlement.ID` 为 key 存 List/Dictionary。取用统一 `Find.World.GetComponent<WorldComponent_Territories>()`。
- ∴ 边缘外政核心应**新建平行 `WorldComponent_EdgePolitics : WorldComponent`**（按 loadID 存双线认可度/暗杀冷却），**不往 FactionDef 挂 modExtension、不复用 BOTR 私有 Tick*System**。
- Tick 中枢 `WorldComponent_Territories.WorldComponentTick()`：`if(TicksGame%60==17)` 后**顺序**跑 `TickTerritorialExpansion→…→TickDependencySystem→TickPoliticsSystem→TickStabilitySystem→TickPlayerRecognitionSystem→TickWarSystem→TickMissionSystem→…`；子 tick 内部各按 `next*CheckTick` 日级(~60000)节流。要"外政读到最新领土/战争态"→ 加**薄 postfix on `WorldComponentTick`**，排在末尾再跑 B 的低频 tick；**不改它的私有方法**。

## 1. 双线认可度（新造，镜像 BOTR 单线范式）

BOTR 现状（private 字段 + public getter）：
- 分：`playerRecognitionScore:float 0–100`；五分项 `playerTerritory/Population/Diplomacy/Service/LongevityStanding`；`RecalculatePlayerRecognitionScore()`(private)。
- 承认方：`playerRecognizingFactionIds:HashSet<int>`(private)；`IsPlayerRecognizedBy(Faction)`(public)。
- 阶梯：`enum PlayerStateRecognitionStatus{FrontierColony,TerritorialClaimant,DeclaredState,RecognizedPower}`；`PlayerRecognitionThreshold` clamp 45–80。
- 公开写：`ProclaimPlayerSovereignty()`、`NotifyPlayerMissionCompleted(Faction sponsor)`。

B 层设计：两套并行实例 `{imperial, free}`，各含 `standing:float` + `recognizers:HashSet<int>` + `status阶梯`。
- 分轨判据：目标派系 ∈ `DependenciesForOverlord(宗主)` 从属树 → 记入 imperial 线；否则 free 线。
- 事件换算：完成 C 层任务/贸易/主权 → 按任务的 `阵营线` 属性给对应线加分（镜像五分项：领土/服务/外交/人口/长线）。
- 好感落库仍走原版 `Faction.TryAffectGoodwillWith`（BOTR 全部好感也走它，见反编译多处调用）→ **与 BOTR 零冲突**。

## 2. 暗杀事件（好感/敌对驱动；走原版，避开 BOTR 占用）

- 解锁：**不再设间谍网/渗透进度**（好感度足够）——目标线认可过低 或 BOTR `FactionBorderContact{tension:float 0–100, 阈值 30=要求/70=开战}` 超阈时抛 ChoiceLetter。阈值判定纯读 public getter。
- BOTR 自身 Harmony **只 patch 原版/Odyssey**：`Caravan.GetGizmos`、`SettlementDefeatUtility.CheckDefeated`、`GravshipUtility.*`、`Quest.Accept`、`TileFinder.IsValidTileForNewSettlement`、`WorldObject.GetGizmos` 等；**未 patch** `Faction.*` 好感 / `Pawn` 死亡健康 / `Pawn_RelationsTracker`。
- ∴ 暗杀可自由挂：`Pawn.Kill`/`HealthCardUtility`/`Pawn_RelationsTracker`，结算走 `Faction.SetRelationDirect`/`TryAffectGoodwillWith`。**须避让** BOTR 已占的 `CheckDefeated`、`Quest.Accept`（若 B/C 也接 Quest，注意与其 `Patch_Quest_Accept_TerritorialMissionConfirmation` 的叠加顺序）。
- 后果接回外政：目标领袖死亡 → 尝试诱发 `TerritorialWar{isCivilWar,isIndependenceWar}`（private，经好感/从属间接影响，不直接调）；**成功→加 free/imperial 线好感，失败→不扣好感**（可仅升目标警戒/定向 `RaidEnemy`，不动委托好感）。

## 4. 帝国从属：三层现成建模 + 宗主候选

**"帝国/Empire"在引擎层无原生从属字段**（1.6 已删 `goodwillMax/Min`，改用 `GoodwillSituationDef`+`Find.GoodwillSituationManager` 每 1000 tick 聚合）。三层组合：

1. **静态阵营划界** = `PatchOperationAdd/Replace` 打 `Defs/FactionDef[defName=X]/permanentEnemyToEveryoneExcept`（List\<FactionDef\> 白名单）。工作区先例：`HSK修复整合\Patches\11_鼠族王国开局中立.xml`（xpath 存在性门控版）；部署版参照(只读，不在工作区)：`Mods\RatkinRaceHSK\1.6\Patches\permanentEnemyToEveryoneExcept_Patch.xml`。目标 def 无 `Class=` 时改属性用 `PatchOperationAttributeSet`。
2. **好感上限/开局盟友** = `Mods\鼠族HSK拓展\Assemblies\Meow.dll`：`Meow.FactionDefExtended <InitAllyTo>`（开局 Ally、baseGoodwill=100）+ `Meow.GoodwillSituationWorker_AlwaysAlly`（`MaxGoodwill=200` 破 100 上限）。配自定义 `GoodwillSituationDef` 即生效（先例 金鼠族 `OAGene_HasHegemonicFlag`）。→ 承载"从属对宗主永不服"。
3. **运行时真从属状态机** = BOTR `TerritorialDependency{type∈{VassalState,Protectorate}, overlordFactionId, subjectFactionId, autonomy, nextReviewTick}` + `EstablishDependency/ReleaseDependency/ReviewDependency/DependenciesForOverlord/DependencyForSubject`（多 private，`TryCreateVassalFromWar` 受 `settings.enablePoliticalDependencies` 开关）→ 权威数据，反射调或读。

## 5. 任务大修 C# 挂钩点（Layer C 重构用）

自研 `QuestBoardHSK.dll`（`任务大修HSK\1.6\Source\QuestBoardHSK\`）。引导：`ModEntry.cs` `[StaticConstructorOnStartup] QuestBoardBootstrap` **逐类 try/catch 打补丁**（一枚失配不崩全场）；`Game.FinalizeInit` postfix 注册 `BountyRadioManager(Game game)`。

重构相关补丁（`HarmonyPatches.cs` 目标均无重载）：

| 维度 | 挂钩点 | 现状 | 重构动作 |
|---|---|---|---|
| 生成/等级 | #1 `WarrantsManager.GenerateRandomWarrant` Prefix(限流)+Postfix(科技门槛 `BountyRules.TechGapOk`+`IsWorldNpcFaction`) | 无 tier 字段 | postfix 里定 tier/弃单；新 `TaskTierDef`/DefModExtension |
| 奖励 | #8 `WarrantsManager.AssignRewards(Warrant_Pawn)` Postfix：`身价×AcceptTechMult×RelationMult`；实物 `BountyRewards.cs` 按 FNV-1a(loadID) 选池 | 唯一金额源点 | 改表驱动 `f(tier×双线认可×科技×从属)`；实物池改 XML `RK_悬赏实物奖励池` |
| 期限 | **无现成补丁**：15 天到期/`tickToBeCompleted` 在 SW 内部未挂钩 | — | 新增 Harmony(需反编译 SW `WarrantsManager` tick 函数) 或仿 `BountyRadioManager` 自管轮询 |
