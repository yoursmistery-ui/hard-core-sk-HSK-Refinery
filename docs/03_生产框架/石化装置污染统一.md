## 2. 统一实现
### 2.1 CompPolluteOnDestroy 扩展为三模式(与 §C.2 同一 comp)
- 数据源 `mode`:
  - `stack` — 物品按堆叠数(Asphalt 用);
  - `stored` — `Building_Storage` 按罐内实存物品数(复用 DLL 已有 `PetroGasUtil.CountInStore` 反射模式, RK 罐都是气/油以松物品存罐);
  - `nominal` — 固定名义值(装置/第三方罐用)。
- props: `cellsPerUnit=6`(与原版守恒)、`maxCellsPerEvent=60`(单事件上限)、`nominalUnits`。
- 触发与铺法不变: 伤害 ≥ 余 HP(烧毁/炸毁/烂掉)或非友好拆除(`GasHazards.FriendlyRemoval`)→ 原版 `PollutionUtility.GrowPollutionAt`;未开 Biotech 直接短路。
- 全部调用**原版 API**: 爆炸=原版 CompExplosive、毒气=原版 gasGrid、污染=原版 pollutionGrid, 三通道零自定义效果。

### 2.2 挂载清单
| 目标 | mode | 建议参数 | 写法 |
|---|---|---|---|
| RK 五对储罐(沥青/石脑油/天然气/氨/中性胺 ×2 形制) | `stored` | cellsPerUnit=6(满罐≈上限内) | 自有 def 的 comps 直接加一行 |
| RK 装置 9 座 | `nominal` | 按 footprint: 2×2≈24、3×3≈54、工作台/锅炉/发电机 12 | 自有 def 直接加 |
| Rimefeller `OilStorage` / `FuelStorage` | `nominal`(基础版) | 原油 90 / 燃油 45(原油罐大) | 补丁: 顶层 Conditional(xpath 存在性)→ Sequence[Add comp], 双 def 各一条 |
| Rimefeller 5 精炼厂 / 油井×2(可选) | `nominal` | 12~24 | 同上, 可选项 |
| 物品 `Asphalt` | `stack` | 6 | §C.2 已定 |
- 顺序注意: 加 comp 的补丁打在 Rimefeller def 上, 按 AGENTS 铁律用 xpath 存在性门控, 不用 Operation 级 MayRequire。

### 2.3 边界与决策
- **气管网 管/阀/泵 不挂**: 零散小件全图遍布, 逐件计污染既烦又无意义;氨的危害已由罐体毒气云承担。
- **并存不替代**: 爆炸照炸、氨毒气云照放、污染格照铺——火/毒/土三通道叠加, 不动现有任何危害行为。
- RK 沥青罐名不副实的 description 顺带修复: 挂 comp 后"泄漏"成立(污染即泄漏);是否再补小半径 `CompProperties_Explosive` 由施工定(建议补, 半径 2)。
- 二期可选(进阶): Harmony 读 `CompStorageTank.pipeNet.TotalOil` 按罐摊分实存值替代 nominal;桥接 `OilSpillGrid.AddAt → GrowPollutionAt`, 让坏抽油机漏油等 Rimefeller 私有泄漏也自动进闭环。

## 3. 最终体验与复核
- **玩家侧闭环**: 石化链任何一次事故(罐爆/装置炸/油罐毁)→ 留下一片原版毒土 → 画清除区 → 清出废料包 → 冷冻/分解器/污树/发射消纳。石化大修与污染闭环完全同构: **事故 = 可清理、可回收、可消纳的资源循环**。
- 施工复核:
